# 书海阅读 · BookSea Reader

墨水屏设备上的小说阅读器。搜索 → 目录 → 缓存 → 离线整本下载，为 **1.9 寸级别的横条屏 + 物理按键 + 触摸** 的形态专门做过排版与性能优化。

当前版本 **1.1.89**。运行环境是 **Weex 样式子集 + QuickJS** 的小程序框架，没有 DOM、没有 `fetch`、没有 `calc()`，因此代码里很多写法看起来"绕"，都是被平台约束逼出来的——下面「实现要点」一节逐条说明了原因。

## 功能

- **搜索**：多书源并发搜索、按书名模糊匹配、同名书自动归组、按来源数排序
- **目录**：分章抓取、按屏翻页、数字键盘直接跳章、章节进度标记
- **阅读**：点按翻页 / 上下拖动滚动两种模式，字号四档切换，进度自动保存
- **缓存**：按章预取、后台持续下载、断点续传（重启应用也能接着下）
- **整本下载**：指定起止章节、失败重试、进度条常驻
- **书源**：支持导入第三方书源规则（JSON 路径提取 + 常见编码/去广告处理）
- **本地书库**：书架统计、占用空间、按书清理

## 实现要点

### 1. 单文件页面 + 数据驱动视图

框架没有路由，`navTo` 传参也不可靠。整个应用是一个页面，用 `view` 字段切换 15 个视图（`home / search / results / toc / read / settings / cache / ...`），每个视图是同一个 `.bd` 容器的一个 `v-if` 分支。

模板里不能有 `<text>` 嵌套 `<text>` 之外的复杂嵌套（会静默渲染失败），所以列表都用「按屏开窗 + 索引数组」而不是滚动容器——这框架没有 `scroll-view`。

### 2. 网络层：`execShell` + `curl`

QuickJS 里没有 `fetch` / `XMLHttpRequest`，网络只能走：

```js
global.execShell("curl -s --compressed -m 20 '" + url + "' > '" + file + "'")
```

因此每次请求都是「curl 落盘 → 读文件」两步。写了一层 `getText()` 把这些封装掉，并处理了：编码嗅探（GBK/UTF-8）、gzip、空响应、超时重试、请求并发上限。

**备用通道**：`execShell` 来自 `global` 原生模块，某些固件上这个模块不可用，此时应用能进但「一搜索就空」。因此加了一条兜底——框架自带的 `$falcon.jsapi.http`：

| 通道 | 前提 | 用在哪 |
|---|---|---|
| `execShell` + `curl` | 有 `global` 模块 + 系统 `curl` | 默认，所有请求 |
| `$falcon.jsapi.http` | 框架内置（基于 libcurl） | 仅在 `shellBroken()` 为真时启用 |

`httpGet()` 里手写了 UTF-8 解码（QuickJS 没有 `TextDecoder`），否则中文全是乱码。落盘同理：`fs.writeFile` 不可用的固件会切到 shell 的 base64 写入通道，写完读回校验。

### 3. 排版引擎：自己折行、自己分页

`src/lib/text.js` 是一个不依赖任何 DOM 的中文折行器：

- 汉字按 1em 计宽，西文按字符宽度表估算，避免了逐字测量（平台没有 `measureText`）
- 避头标点（`，。！？、；：）】》」』"'…—`）不另起一行，宁可让上一行略超
- 折行用「下标切片」而不是逐字拼字符串，一章 3000 字从 57ms 降到 7ms

分页结果是 `[{lines, start, end}]`，翻页只换 `lines` 引用，不动整章节点。

### 4. 性能：慢的不是计算，是重绘

一开始阅读页拖动明显掉帧。加了采样后发现 JS 侧只占 7ms，真正的成本是**整章一次性渲染成 168 个文本节点，每帧全量重排**。三处改动：

| 问题 | 改法 | 效果 |
|---|---|---|
| 整章 168 个节点每帧重绘 | 只渲染视口附近 11~14 行，位移只改 `translateY` | 141ms → 34ms |
| 一次拖动十几个 `touchmove` 各自重排，事件排队越拖越远 | 合帧：只保留最新位置，上帧画完再应用 | 拖动手感跟手 |
| 手势字段（`tsX/tsY/tsN`…）放在 `data` 里 | 移出 `data`，改普通实例字段 | 一次拖动不再触发十几次全模板重绘 |

第三条尤其反直觉：这些字段从不进模板，但只要在 `data` 里就是响应式的，写一次就整模板重绘一次。

其他：`syncChrome()` 原来每帧重建设置页行数组；`onTouchStart` 每次 `JSON.stringify` 整个事件对象；网络探测 `curl -m 4` 在同步 `execShell` 里把界面冻 4 秒。都已改掉。

### 5. 自适应：等比缩放为主，几何偏移兜底

设计稿是 936×280，但同系列设备有多种逻辑分辨率（960×266、1024×300、800×480…）。高度少 14px 就足以把底部按钮顶出屏幕，宽度不同则会把右侧文字截掉。

**不能用纯 `vw/vh` 解决**：Weex 子集没有 `calc()` 也没有 `min()`，"宽度不溢出 + 高度不溢出"需要取 `min(W/936, H/280)`，样式表无法表达。（另外实测这台设备上 `100vh` 只解析成 250，不是 280——官方文档写明 `vh` 是「相对 device width 的百分比」。）

主路线是官方推荐的 `setViewPort(设计宽)`：框架把虚拟画布等比缩放到真实屏幕。但它只按**宽**定缩放比、高度跟着同一个比例走，直接传 936 会在更扁的屏上切底部。所以反解出虚拟宽：

```js
const scale = Math.min(W / 936, H / 280)   // 取小者：整张设计稿一定装得下
this.setViewPort(W / scale)                // 等价 max(936, W * 280 / H)
```

整张设计稿等比进屏，比例不同时留一圈底色，**任何机型都不裁内容**。真机实测（936×280）：缩放确实生效（基准改 700 → 内容放大 1.34 倍）、缩放发生在合成层（渲染树仍是设计值）、触摸坐标会被换算回设计空间（左右半屏翻页分界不用改）。

`applyViewPort()` 的结果写到 `globalThis.__shVP`，页面据此二选一：

| 情况 | 布局方式 |
|---|---|
| 缩放成功 | 全部按设计稿 936×280 算，留边交给缩放比 |
| 无 `env` / 无此方法 / 抛错 | 退回 `geo.js` 的「设计稿值 + 同一偏移量 `dh`」 |

兜底路线是个**代数恒等式**，任何屏高都成立：

```
body(217+dh) + 顶栏 33 + 底栏 30 = 屏高
```

`geo.test.mjs` 有 210 条断言：几何偏移覆盖 936×280 / 960×266 / 1024×300 / 800×280 / 640×480 / 竖屏误报 / 0×0；等比缩放覆盖「虚拟宽 = 真实宽 / 缩放比」的反解自检，以及 800×480 / 480×640 / 800×240 / 1280×320 下**画布绝不超出屏幕**（不裁内容的数学保证）。

一个坑：**两条路线不能叠加**。缩放生效后再按「屏高 − 280」平移，等于把余量算两遍，底栏会被推出屏幕。`applyGeo()` 里用 `scaledUI` 明确互斥。

## 构建

需要框架自带的 `aiot-cli`（随开发环境安装）：

```bash
npm install
npm run build:prod     # 产出 <appid>.<version>.amr
npm run bump           # 版本号 +1（产物按版本命名，不升版本会分不清装的是哪个）
```

单测（纯 Node，无需设备）：

```bash
node test/geo.test.mjs     # 几何推算
node test/lib.test.mjs     # 折行/分页/解析
node test/hist.test.mjs    # 历史记录
node test/multi.test.mjs   # 多源合并
node test/light.test.mjs   # 轻小说源
```

## 已知限制

- **模块本体缺失会白屏**：`import fs from 'fs'` / `import global from 'global'` 是顶层静态导入，框架只支持静态 import，try/catch 救不了求值阶段，模块不存在时应用直接启动失败——这一点无法在应用层消除。但「模块在、某个方法没有」的情况已经兜住：`fs.writeFile` 缺失切 shell base64 写盘（写后读回校验），`execShell` 缺失切 `$falcon.jsapi.http`。
- **书源质量决定一切**：内置规则依赖第三方站点结构，站点改版会导致该源失效，需要在「书源」页更新规则。
- **缓存速度受站点限速**：实测约 15 章 / 30 秒，千章级书籍完整缓存需 1 小时左右。应用切后台仍会继续（定时器不随视图切换停止），但设备息屏被系统回收时会中断——已做断点续传。
- 阅读页底栏占 30px，正文可视高度比同尺寸原生阅读器略小；这是为了按钮可点面积做的取舍。
