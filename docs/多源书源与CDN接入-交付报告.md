### A.4 本轮测试中发现并修掉的 5 个真实 bug（都会让「多源」看起来完全不可用）

| # | 现象 | 根因 | 修复 |
|---|---|---|---|
| 1 | 50 条结果的书名全是第一本书 | 逐条规则（`ruleSearch.name` 等）永远从**整页根节点**求值，`ctx.item` 没用上 | `evalOne` 有行节点时从**这一行**开始找 |

## C. CDN 测试表（真实请求，2026-11-10 12:13）

目标文件：`XIU2/Yuedu@master/shuyuan`（163,824B / 22 条书源）。直连，不走本机代理。

| 线路 | HTTP | 总耗时 | 内容 | 校验 | 分阶段（DNS / TCP / TLS / TTFB） |
|---|---|---|---|---|---|
| jsDelivr | 200 | **259ms** | 150,136B | ✅ 22 条 / fnv1a `832f30cc` | 8 / 69 / 143 / 204ms |
| Statically | 0（TCP 不通） | 6052ms | 0B | ❌ 超时 | 12 / — / — / 6012ms |
| raw.githack | 0（TCP 不通） | 6056ms | 0B | ❌ 超时 | 4 / — / — / 6012ms |
| GitHubRaw（cdn.githubraw.com） | 200 | 2094ms | 150,136B | ✅ 同上 | 28 / 296 / 665 / 2020ms |
| GitHub Raw（raw.githubusercontent） | 200 | **221ms** | 150,136B | ✅ 同上 | 5 / 57 / 119 / 172ms |

- **三条成功线路的文件指纹完全一致**（`832f30cc`），说明镜像没有给错版本。
- **故障切换实测**：把首选线路的仓库名故意写错 → `jsDelivr 404 → Statically 超时 → githack 超时 → GitHubRaw 成功（1035ms）`，拿到的是**同一个文件**（校验通过、指纹一致），且失败线路只被标记 `ok=false`、**没有被永久禁用**。
- 未做 SHA-256 跨线路比对的原因：`sha256` 纯 JS 实现已在 `cdn.js` 里（单测校验过 `abc` 的已知值），但设备端整文件算哈希成本高，默认只存 `fnv1a` 短指纹；需要时可在设置页手动触发。
- 结论：国内网络下 **jsDelivr 为主、raw.githubusercontent 为备**，statically/githack 在本机不可达（不删线路，只标不可用，供换网络环境后重测）。

## D. 搜索机制（已实现的行为）

1. **候选集**：`enabled === true` 且 `status !== 'bad'` 的源；不兼容的源不参与（否则白等一次超时）。
2. **顺序**：按 `priority` 升序，并发池默认 3（设置页 1/2/3/5 路可调）。
3. **单源隔离**：每源独立 `timeout`（6/8/12s 可调）+ `retry`（0/1/2 次）；失败/超时只记在该源上，不影响其它源。
4. **部分成功先展示**：`onPartial` 每回来一个源就重排一次并刷新列表，顶栏显示「搜索中… 3/8」。
5. **整体兜底**：`overallTimeout`（≥15s）到点强制收尾，已拿到的结果照常显示。
6. **去重**（默认开）：书名归一（繁简 + 去书名号/空格/「最新章节」等噪声）+ 作者归一 + 相似度 0.86 阈值；判定规则：
   - 名同 + 作者同 → 合并（高置信）；名同 + 作者缺 → 合并（低置信）
   - 名近（≥0.86）+ 作者同 → 合并；其余 **不合并**（宁可两条，不合成一条）
   - 合并后一条记录带 `sources[]`，各源保留自己的 url/bid/最新章节/状态/登录标记
7. **排序**：完全匹配 +100、前缀 +60、包含 +40、作者命中 +40、多源 +8、可用源 +10；**不按响应速度排**。设置页可切「匹配度 / 优先级」。
8. **缓存与防重复**：同源同词 10 分钟 TTL；进行中的相同请求共享同一个 Promise（`cache.once`）；只有点「重搜」才 `refresh=true` 绕过缓存；切源时只请求没搜过的源（`searchSubset`）。
9. **失败可见**：结果为空时把前两个失败源的原因直接写在空态里（如「无错小说①：页面能开但解析 0 条」）。

## E. 设置页说明

设置页新增 3 行入口：

**书源管理**（`view='sources'`，一次 4 行 + 翻页）
- 顶栏：`全选 / 全不选 / 测试全部 / 导入破冰 / 导入女频` + 一行提示
- 每行：名称 · 状态（可用/部分可用/需登录/暂时失效/待测试/不兼容 + 耗时）· `启用|停用` · `测试` · `上移` · `删除`
- 分页条：`返回 / 第 x/y 页 · 启用 n/总数 / 上一页 / 下一页 / 搜索设置`
- 全选**跳过**不兼容源（选了也搜不出）；内置源不能停用/删除；一次点「测试全部」= 测所有已启用源（一个都没启用则测当前页），再点一次**中途停止**并给出统计
- 单个「测试」跑完整链路：搜索 → 目录 → 正文，逐级报告卡在哪一步（例如「目录 HTTP 200 但 0 章」）

**CDN 线路**（`view='cdn'`）
- 顶栏：`全选 / 全不选 / 测试全部 / 更新书源`
- 每行：名称（首选会标出来）· 可用/不可用/未测试 + 耗时 · `启用/停用` · `测试` · `上移`
- 「更新书源」= 按优先级依次试 → 校验内容（拒 HTML/限流/缺 `bookSourceUrl`/条数不足）→ 合并导入（保留原启用状态）→ 失败时**保留旧配置**

**搜索范围**（`view='netset'`）
- 并发 1/2/3/5 路、超时 6/8/12s、重试 0/1/2 次、去重开/关、排序（匹配度/优先级）、当前启用源数（可直接跳书源管理）
- 所有改动即时落盘 `net.json`

**来源选择**（`view='pick'`）
- 详情（目录页）出现`换源 N`按钮（仅当这本书有 >1 个来源）；列出各源：名称 · 状态 · 最新章节 · 是否需登录
- 切换后**重新抓该站目录**，章节地址不混用；目录页顶栏显示「共 N 章 · 源名」

配置文件（都在数据目录，`saveBoth` 双通道 + 写后读回）：`sources.json` / `cdn.json` / `net.json`；第三方书额外写 `bookDir/<bid>/src.json`（记住「哪个源、哪本书地址」，书架重进才能续上）。
